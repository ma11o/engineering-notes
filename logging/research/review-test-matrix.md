# ログ設計レビュー用チェックリスト（学習用）

更新日: 2026-10-07。これは組織の採用済み規則でも、法令適合性の判定表でもない。まず人が目的・記録単位・許容リスクを決める。自動化欄は、合意した制約を検査する候補であり、CIへの実装・動作検証はしていない。

根拠: [論点別まとめ](external-evidence.md)、[A: イベント・相関](sources/event-correlation.md)、[B: レベル・結果](sources/severity-outcomes.md)、[C: 情報保護・保証](sources/log-guarantees.md)。下記のテスト方法はこれらからの独自提案。

| 観点 | 人が判断すること | lint / CI / 試験の候補 | 自動化だけでは保証しないこと |
| --- | --- | --- | --- |
| 目的・粒度 [A/B] | 誰のどの問いに答えるか。受信操作、依存呼出し、試行のどれを1件とするか | 定義済みイベントの必須項目・型・単位・発火条件の契約テスト | そのデータが調査に十分か、母数が適切か |
| 名前・属性 [A] | eventの種類と個体ID、BodyとAttributesの役割。採用する規約・版 | 固定イベント名の一覧照合、型、列挙値、可変IDを埋めた名前の検出 | OTelに似た名前だけでの準拠、任意のイベント意味の正しさ |
| 時刻 [A] | 発生時刻と観測時刻、欠損や時刻ずれをどう読むか | フォーマット・単位・変換のテスト。ゼロ／欠落ケース | クロックの正確さ、時系列だけからの因果 |
| 相関 [A] | 生成・継承・破棄、信頼境界、リトライ／非同期の識別範囲 | 不正traceparent入力、HTTP→キュー→ワーカー、並行処理のコンテキスト混線を試験 | IDの一致による本人性、全経路の完全性、外部システムとの契約 |
| 結果・severity [B] | 想定内拒否、回復、最終失敗、呼出し元への影響 | 決めた対応表を代表シナリオで検査。エラー型の固定性 | 全4xx/例外の機械的なレベル分類、業務上の成功 |
| 重複・母数 [B/C] | 下位例外と最終失敗を区別するか。正常比較対象はあるか | リトライ成功／枯渇時の件数、再送重複の統合テスト | ログ件数が実操作数であること、欠損のない母集団 |
| 通知 [B] | 今、人が何をするか。ユーザー影響、緊急度、通知先 | 合意した通知条件・抑制・復旧通知のシミュレーション | ERRORがページングに値すること、閾値の適切さ |
| 情報最小化 [C] | フィールドごとの必要性、秘密／個人情報、本文の代替値 | allowlist、既知secretパターン、合成機微データ、CR/LF等の注入テスト | 未知の機微情報の不存在、ハッシュによる匿名化、法令適合性 |
| 出力経路 [C] | SDK前、stdout、ファイル、Collector、バックアップのどこに原文が残るか | redactionの前後、経路分岐、失敗時フォールバックの合成データ検査 | 後段除去だけでの全経路保護、全バックアップ消去 |
| カーディナリティ・費用 [C] | 個別IDを属性／索引／メトリクスラベルのどこに置くか。予算と調査価値 | 禁止ラベル、サンプルでの種類数・サイズ・発生頻度の計測 | テスト分布からの本番費用保証、全保存先への一般化 |
| 欠損・サンプリング [C] | 何が残らないか。エラーを必ず残す要件が本当に必要か | 停止、キュー満杯、再起動、遅延到着、再試行期限の障害注入 | head/tail samplingによる完全性、永続キューによるゼロ損失 |
| 監査・保持 [C] | 証跡の用途、必要な網羅性、改ざん耐性、閲覧者、期間の根拠 | 設定差分、アクセス権の検査、合成記録の検索・期限処理のテスト | 観測ログによる監査要件充足、普遍的な保存期間 |

## 合意を残すための最小メモ

- 調べたい問いと利用者:
- 記録する出来事・発火時点・処理単位:
- 正常／拒否／回復／最終失敗の代表例:
- 採用する仕様・意味規約・製品とバージョン／状態:
- 属性ごとの必要性、機微性、欠落時の意味:
- 伝播する境界と信頼の扱い:
- 収集欠損・重複・サンプリングが問いへ与える制約:
- 保持・アクセス・監査保証を決める責任者と根拠:
- 自動チェックする合意事項／人が確認する残余リスク:

このメモを埋めるために実システムや組織情報が必要なら、その調査は別の許可・作業範囲として扱う。
